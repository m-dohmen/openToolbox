# openToolbox

[English](README.md) · [Deutsch](README.de.md) · **中文** · [Español](README.es.md) · [Français](README.fr.md) · [日本語](README.ja.md) · [Português](README.pt.md)

**把一个可用的内部工具做成单个 HTML 文件交付。无服务器、无需安装、不联网。**

openToolbox 是一个模板，用于那些需要四处流转的小型内部工具——通过邮件、U 盘或共享盘传递，在权限受限的公司笔记本上双击即可运行。这个文件**同时是**应用程序和数据库：保存时会写出一个新的 HTML 文件，数据就嵌在里面。

它是为一种特定的工作方式而生的：

> “基于 openToolbox，帮我做一个跟踪供应商审计的工具。”

把 AI 编码代理指向这个仓库，它就拥有了所需的一切——框架本身，以及告诉它该问什么、该改哪个文件的 [`AGENTS.md`](AGENTS.md)。

还能再省一步：安装 [`plugin/`](plugin/) 里的 skill 后，在任意目录描述你想要的工具即可，代理会自己取来模板。Claude Code 和 Codex 读同一个 `SKILL.md`——安装方式见 [`plugin/README.md`](plugin/README.md)。skill 并非必需，上面那句话不装也能用。

## 你会得到什么

- **一个文件。** 约 240 KB，自包含。双击即运行。拔掉网线依然可用——唯一会缺失的是[使用计数器](#使用计数器)，而它离关闭只有一个可见的开关。
- **文件即数据库。** 保存会写出一个嵌入了记录的新 HTML 文件。没有后端，不用浏览器存储，无需同步。
- **可选加密。** AES-256-GCM，密钥通过 PBKDF2 迭代 310,000 次派生。没有口令，文件就是一团乱码。
- **可选 AI 助手。** 指向任意兼容 OpenAI 的端点。它读取数据、接受文件附件作为额外上下文，并在收到明确指令时提出修改建议——由你批准后才会应用。
- **可定制外观。** 五种颜色、产品名和一个 SVG 图标，都能在应用内修改并随文件保存。
- **明暗两种主题**、键盘快捷键、CSV 与 JSON 导出，窄至手机宽度依然可用。
- **带列映射的 CSV 导入**，真实数据无需重新录入。
- **两种界面语言**（英语、德语），设置随文件一起流转。
- **多种记录类型及其关联**，当一种不够用时。
- **仪表板磁贴与打印样式表**，因为分析工作通常止于一页幻灯片或附件。
- **仪表板上的到期提醒组件**，用一个模式字段开启——逾期、本周、未来 30 天，跨所有声明该字段的实体汇总。
- **变更日志**，每次保存都记录日期、版本和改动说明。
- **内嵌的示例提示词**，让接收者无需读这份文档也能让工具被修改。
- **设置页面的锁**，让只负责录入数据的人拿到工具后不会误改配置。
- **可编辑的顶栏文字和最多 5 个链接**，指向工具旁边的东西（仓库、内网目录、工单板）。
- **跨字段的校验规则**，在表单、CSV 导入（含向导中的 CSV 步骤和 JSON 导入）以及 AI 提出的改动上以同一套逻辑生效。
- **引导式录入向导**，以及直接以向导打开文件的收集模式，适合只需报告一件事的收件人。
- **合并回收的副本**，逐条记录处理，变更按字段列出新旧值。
- **字段级变更记录**，每次保存自动比对：哪条记录、哪个字段、改动前后各是什么。
- **带可见容量预算的附件**，因为一个再也发不出邮件的工具，就不再是这个工具了。
- **可编辑的起始页**，让文件在展示表格之前先自我说明。
- **本次会话内的撤销/重做**，覆盖每一次新建、编辑和删除，用 Ctrl/Cmd+Z 与 Ctrl/Cmd+Y，或文件栏里的两个按钮。
- **跨所有实体所有字段的全局搜索**，实时过滤，标签页上显示命中数，表格中高亮匹配；侧边栏还有按字段类型的筛选器和可移除的筛选标签——仅限当前会话，不会写入文件。
- **实体列表的每一列都可排序**——点击一次升序，再点降序，第三次恢复数据块顺序；比较按字段类型进行（数字按数值、日期按时间），空值始终排在最后。
- **一键复制记录**——从表格行或打开的表单发起：全部字段值照搬，标题自动加上随界面语言变化的"(Copy)"后缀，副本获得自己的编号；与手工新建走同一条路径——撤销栈、变更日志，保存时才写入文件。
- **多选与批量维护**：逐行勾选、Shift+点击范围选择，或一键选中所有可见行；操作栏可批量设置枚举字段值，或在确认后批量删除——每次批量操作只记一条历史，一次 Ctrl+Z 即可全部撤销。
- **仪表板上的指标卡片**——schema 声明 `metrics`，每条声明生成一张卡片：`count`（可带筛选条件）、`sum(字段)` 或 `avg(字段)`，仅限数值字段；渲染时本地计算，不写入数据；点击卡片跳转到对应实体列表；无效声明会被点名拒绝，而不是静默忽略。

## 快速开始

```bash
git clone https://github.com/m-dohmen/openToolbox
cd openToolbox
npm install
npm run build     # → dist/index.html
```

在浏览器中打开 `dist/index.html`。就这些。

## 构建你自己的工具

所有与业务领域相关的内容都在**一个文件**里：`src/domain.js`。替换它，重新构建，完成。

```js
export const SCHEMA = {
  singular: 'risk',
  plural: 'risks',
  titleField: 'name',
  list: ['name', 'owner', 'review', 'likelihood', 'impact'],
  facets: ['likelihood', 'category'],
  fields: [
    { key: 'name', label: '风险', type: 'text', required: true },
    { key: 'category', label: '类别', type: 'enum', values: ['运营', '法务', 'IT'] },
    { key: 'review', label: '复核日期', type: 'date' },
    { key: 'impact', label: '影响程度', type: 'number' },
  ],
}
```

字段也可以是**计算得出**而非存储的：

```js
{ key: 'score', label: '风险值', type: 'computed', compute: (r) => r.likelihood * r.impact }
```

`compute(record)` 在每个记录每次渲染时运行一次，结果会在页面生命周期内被缓存到该记录上——一千条记录经排序、搜索和导出，每个字段仍只调用一次，而不是每轮调用一次。结果**从不写入记录**——这正是关键：一旦某个输入变化，被存下来的推导值当场就错了，而且没人会察觉。排序、搜索、汇总和 CSV 导出照常有效；在表单里它是只读的，AI 也被告知这一点，若试图写入会被指名拒绝。

若 `compute(record)` 抛出异常，该字段渲染为短横线，控制台会针对每一条由实体、字段、记录 id 与错误信息组成的唯一组合打印**恰好一次**警告。表格不会因此中断；同一组合不会重复报警。

`compute` 返回数字的 computed 字段可以在封闭的 `sum(field)` / `avg(field)` 指标目录中替代真正的 number 字段——`totalField` 早已接受这一做法。

仅凭这份 schema 就能生成表格列、编辑表单、侧栏筛选器、CSV 导出、发送给 AI 模型的说明，以及对模型任何回提建议的校验。

## 多种记录类型及其关联

多数工具只需要一种记录类型。一旦确实存在两种以上相互引用的记录（供应商与其证书、项目与其里程碑），就改为导出 `ENTITIES`，并在指向对方的那一方加上 `type: 'reference'` 字段。

引用字段在表单中呈现为目标记录的下拉列表，在表格中呈现为可点击的标记并显示目标标题——点击即切换到该类型并打开对应记录。删除仍被引用的记录会被阻止，并明确指出是谁在引用它。

`examples/portfolio.domain.js`（即上方演示的来源）一次性用上了全部功能。

## 数据怎么进来

**带列映射的 CSV 导入**。选择文件后，对话框会列出识别到的每一列，旁边是字段下拉框。标题与字段标签或键名匹配的列会被预选（忽略大小写和标点）。其余手动指定，未指定的列略过。可选择追加或全部替换。

分隔符（`;`、逗号、制表符）、引号规则和文件开头的 BOM 都会自动识别，因此 Excel 导出无需任何预处理。每个单元格都经过与 AI 建议相同的类型校验。**不会有任何东西静默失败**——结果页会逐条列出问题及其行号，某个单元格出错不影响该行其余部分，缺少标题的行会被跳过而不是导入成半空记录。

标识符始终由应用分配，绝不取自文件。

## 版本号与变更日志

**版本**是设置中的自由文本——`1.4`、`2026-Q3`、`提交指导委员会终稿`。它显示为标题旁的标记，并写入保存的文件名（`project-portfolio-2.1-2026-08-15.html`），这样在有四个附件的邮件线程里，不用逐个打开就能认出哪个是对的。

**变更日志**每次保存写入一条记录：时间戳、版本，以及保存时在简短对话框中填写的说明。这些条目与数据存放在一起而非与设置放在一起——因此在加密文件中，日志位于加密信封**内部**，“审计发现后修正了预算”这类备注本就该在那里。

## 示例提示词

构建出的文件会自己说明该怎么修改。在通常需要调整的位置——页眉、表格、筛选器、仪表板、编辑表单、CSV 导入、AI 面板——会出现一个醒目色的提示框，说明这部分由什么生成，并提供一段可直接交给 AI 代理的提示词和复制按钮。

用意在于：拿到文件的人不必读过这份文档、也不必知道 `src/domain.js` 的存在，就能让工具被改。

默认开启，因为模板的职责是教会人。**在把成品交给只负责录入数据的人之前请关掉它**——对他们而言这些框只是干扰。

## 为什么是单个文件

在受监管环境和大型企业里反复出现的三条约束：

- 托管一个小工具意味着一台服务器、一个网址、一位运维负责人，通常还有一轮安全评审。
- 安装任何东西都需要用户没有的管理员权限。
- 数据不得离开这台机器。

单个 HTML 文件绕开了这三条。而且它对自己的身份是坦诚的：用户可以读到全部源码，也不存在某个会在他们背后悄悄改变的服务。

## 锁定设置

设置 → 安全 → *保护设置* 会要求输入一个词，并禁用该页面上的所有控件。字段仍然**可见，值也仍然可读**——传达的是“现在别动”，而不是“与你无关”。同一个词可在当前会话中重新启用它们；重新打开文件后又会锁上，保护不会在作者第一次保存后悄悄消失。

**这是防误操作，不是安全边界。** 拿到文件的人也拿到了代码，锁的记录可以用文本编辑器从数据块里删掉。它是开关上的一个盖子。真正不能被读到的东西请用加密——那个是真的。

这个词也不是密码。它以加盐 SHA-256 摘要的形式保存，因此不会以明文留在文件里；但输入框故意明文显示它：没人该为一个盖子重用真实密码，“123” 就够了。没有复杂度规则。

## 使用计数器

构建出的文件唯一会主动联网的地方。打开时发送一次 GET 请求，携带**这是哪一类工具**（`SCHEMA.singular`，例如 `action item`）。仅此而已：不含记录、不含字段内容、不含文件名、不含任何输入的内容。

三个刻意的设计，因为这类文件会被转交给并非构建者的人：

- **端点是一个可见、可编辑的设置**，预设为模板作者的计数器。可以指向你自己的，或清空该字段则完全不计数。设置随文件一起流转。
- **它是一个带标签的开关**（设置 → 安全），旁边写明目标地址。不是隐藏的像素。
- **路径携带的是工具类别，绝不是文件名。** 文件名可被接收者修改，实践中常带有客户名称（`kunde-xy-risikoregister`）；把它发给第三方等于泄露属于文件接收者的信息。

关掉计数器、关掉 AI 集成，这个文件就**不会**打开任何网络连接。可在网络面板中验证，测试套件也对此做了断言。

## 需要了解的局限

- **没保存就是丢了。** 没有自动保存——没有目标文件就无从自动保存。文件栏的琥珀色圆点和关闭标签页时的提示是仅有的防线。Ctrl/Cmd+S 保存。
- **一台机器，一个文件。** 没有多用户模式。两个人各自编辑同一个文件，会产生两份互不相容的事实。
- **邮件网关经常拦截 `.html` 附件**。打包成 zip 或使用文件传输服务，并在真正需要之前用一个测试文件走一遍流程。
- **加密保护的是数据，而非对应用的访问。** 在本地运行的文件里做角色和视图只是表面功夫——谁拿到文件，谁就拿到了代码。
